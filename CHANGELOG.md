# Changelog

All notable changes to this project will be documented in this file.

## [Unreleased]

### Added
- **CardBoard: edit cards in place, no popup.** `edit_card(key, on_done=, initial=, validate=)` opens the inline editor over a card, `draft_card(slot, ...)` reserves a card-high space at a slot and types a new card there (`compute_layout(..., draft=)`, `BoardLayout.draft_box`). Enter commits, Escape cancels; a validator's message appears below the field (`FieldErrorLabel`) and keeps the editor open; focus loss commits a valid text and discards an invalid one. The open editor follows re-layouts and closes when its target vanishes. One editor class for text cells and cards (`editing` names the target).
- **CardBoard: `LaneKind.CARDS_TEXT`** -- cards with a small "+" above a free text in the same cell (e.g. material above ideas). `CellBox.text_box`, `HitKind.TEXT` for clicks on the text area, slots over the text land at the end of the cards, navigation runs cards then text, a cell cursor frames the text area. `lane_holds_cards`/`lane_holds_text` are the one rule for what a lane holds.
- **Roomy text prompt:** `TextPromptDialogService.askstring` opens a wide, themed dialog (entry at least 520 px, slightly larger font, horizontally resizable, OK/Abbrechen right-aligned) instead of the cramped stdlib prompt. A rejected text (`validate=`) shows its message **inline below the entry** instead of a second popup; the next edit clears it. Same keywords as before (`initialvalue`, `show`, `parent`), so every consumer gets it without changes.
- `bw_gui.widgets.field_error.FieldErrorLabel`: the one look for "this text is not accepted" -- a hideable `Error.TLabel` line below a field (text prompt, CardBoard inline editor).
- **No widget keeps Tk's system colours:** `configure_ttk_theme` themes every classic Tk widget (`Frame`, `PanedWindow`, `Label`, `Menu`, `Text`, `Listbox`, `Canvas`, buttons, …) from one table (`theming/_classic_widgets.py`), for new widgets through the option database and for existing ones after every theme switch. Explicitly set colours stay. A guard test fails for any classic `tkinter` widget class the table misses or any colour still starting with `System` (`THEME_CONTRACT.md`, "Classic Tk widgets").
- Theme tokens `info`, `info_hover`, `info_soft`, `fg_on_info` in every theme (derived sky blue where a theme does not define them; muted by the intensity levels like the other state colours).
- **CardBoard:** `BoardRow.action` shows a small button in the row-label column below the label; a click reports `on_row_action(row_key)` without moving the cursor (`HitKind.ROW_ACTION`, `Hit.row_key`). Look from theme tokens, follows theme switches.
- `Error.TLabel` style (foreground = theme token `danger`) for validation hints in forms, so consumers no longer hard-code an error colour.
- **RadioGroup** (`bw_gui.widgets.RadioGroup`): one exclusive choice among labelled options (`(value, label)` pairs, `StringVar`), optional title, fixed spacing, `first_button` for the initial focus; staged like `Checkbox` (`docs/TOGGLE_CONTRACT.md`). Space activates only without Ctrl/Alt -- the exact-modifier rule now lives in one place for checkbuttons and radio buttons.
- **CardBoard:** `BoardCard.tone` (`CardTone.NORMAL`/`EMPHASIS`/`WARNING`) marks a card through theme tokens (soft accent fill, warning outline) without colours in the consumer; `BoardRow.locked` makes a row take nothing new (no "+", no drop slot, no text editor, no placeholder) while its cells stay selectable.
- `bw_gui.runtime.event_in_toplevel(event, toplevel)`: whether an event happened inside a given window (by Tk path) -- as `applies_when` of application-wide shortcuts, so keys in non-modal tool windows never run main-window actions (`docs/WIDGET_EVENTS_CONTRACT.md`).
- **CardBoard** (`bw_gui.widgets.card_board`, `docs/CARD_BOARD_CONTRACT.md`): rows × lanes of ordered cards (optional code badge) plus free-text lanes with an inline editor; drag & drop shows a coloured insertion line only where the consumer's `can_drop` allows it; "+" boxes per cell; row tints through the theme; keyboard cursor with pure navigation (`move_cursor`, `neighbor`). Binds no keys -- consumers bind on `key_widget`. Tk-free layout, hit testing and slots for unit tests.
- `TextPromptDialogService.askstring(..., validate=...)`: optional check of the entered text; an error message is shown as a warning and the prompt stays open with the text kept (replaces consumer re-prompt loops for rules like uniqueness).
- `bw_gui.widgets.canvas_shapes`: `rounded_rect_points` (pure point list for a smoothed polygon, usable with `CanvasItemPool`) and `create_rounded_rectangle`; moved from Kursplaner so every app draws rounded boxes the same way.
- **Menu item mnemonics** (`MenuItem.mnemonic`): a single letter that runs the item from the keyboard while its popup is open -- also from nested, still closed submenus, case-insensitive and with Alt still held. The letter is shown right-aligned in the row. Duplicate letters within one section's item tree raise `ValueError`, and so do duplicate `MenuDefinition.alt` letters in the strip (previously the second section was silently unreachable).
- `tests/test_consumer_bw_libs_in_sync.py`: fails when the `bw_libs` copies in sibling programs differ; skipped without siblings.
- **Multi-cursor editing** (`bw_gui.runtime.attach_multicursor`, `docs/MULTICURSOR_CONTRACT.md`): several cursors and selections in a `Text`, with one undo step per key press and undo/redo that restores the cursors.
- `bind_drag(..., consume_when=...)`: makes a drag exclusive for some modifiers, so class bindings do not see the gesture.
- **DataGrid** (`bw_gui.widgets.data_grid`, `docs/DATA_GRID_CONTRACT.md`): virtualised canvas table with LEFT | SCROLL | RIGHT regions, two user-resizable splitters, one shared vertical position, cell cursor + row band + active-column marker, sort indicator, global column-width zoom, click/double-click/header events and `cell_bbox` for inline editors. Binds no keys; consumers bind on `key_widgets`. A cursor move costs a small constant number of Tcl calls regardless of the column count (a `ttk.Treeview` re-lays out the whole table on every visible change).
- `IdleRenderScheduler` (`bw_gui.runtime.idle_render`): mark renders dirty, one run per idle cycle in first-marked order, `flush_now()`, cancelled when the owner widget is destroyed.
- `CanvasItemPool` (`bw_gui.widgets.canvas_item_pool`): reuse canvas items across render passes and send only changed coordinates/options; unused items are hidden.
- `bw_gui.testing.tk_root.create_tk_root(factory)`: create a real Tk root for a test; retries the Windows Tcl init race and skips only without a display (or when the race persists), every other `TclError` still fails the test.
- `bw_gui.testing.tcl_calls.count_tcl_calls`: count the real Tcl calls of an action for deterministic budget tests.
- **Native scrollbars with dark mode** (`docs/SCROLLABILITY_CONTRACT.md`): `bw_gui.runtime.widgets.Scrollbar` is now the bw-gui scrollbar primitive -- the slim native scrollbar (no clam arrow buttons) that follows the theme by itself: on Windows a dark theme switches the system control to dark mode, elsewhere the theme colours apply. Every other ttk name in `widgets` is unchanged.
- `bw_gui.testing.scrollbar_guard`: AST guard for consumer apps (no `ttk`/`tk`/`ui.Scrollbar`), with its three levels documented in the module.
- `ThemeChange` and `register_theme_listener` are exported from `bw_gui.theming`.
- **Theme listeners** (`docs/THEME_CONTRACT.md`): `register_theme_listener(callback, *, owner)` runs after the styles of every `configure_ttk_theme` call, exactly once, in registration order with isolated errors; owner-bound lifetime (`WeakMethod`, finalizer). Requests during the listener phase are deferred (last wins), equal states dropped, cycles reported as `RuntimeError`, at most 8 follow-up switches.
- `PointerGroup.on_focus_change(*, on_gained, on_lost)`: focus hooks bound once for all members (table cells committing on focus loss).
- `bw_gui.testing.tk_usage_guard`: shared AST guard for consumer apps (rules `bind`, `sequence`, `break`, `event-field`, `selection`; `find_offenders`, `opt_outs` for `# bw-tk: <reason>` lines), with its three levels (semantic rule, detected patterns, known false negatives/positives) documented in the module.
- `bw_gui.runtime.reset_text_modified(text)`: declares programmatic `Text` content (e.g. a loaded document) as the unmodified baseline, so `on_text_modified` does not report the load (`docs/WIDGET_EVENTS_CONTRACT.md`).
- **Widget events contract** (`docs/WIDGET_EVENTS_CONTRACT.md`): lifecycle hooks `on_resize`, `on_focus_change` (both with `within=True` for a toplevel and its descendants), `on_visibility` (real `winfo_viewable()` transitions only), `on_destroy`, `on_text_modified` (resets Tk's modified flag itself), `on_tab_changed`; widget-specific selection hooks `on_listbox_select`/`on_treeview_select`/`on_combobox_select` with `cause` (`USER`/`PROGRAMMATIC`/`EXPORT_LOST`/`CONTENT_CHANGED`) and de-duplication, plus the mutation objects `listbox_selection`, `treeview_selection` (generation mark against Tk's queued event), `combobox_selection` with `notify`; `on_activate` (Enter or double click on an element). Pointer: `bind_hover` and `bind_canvas_item` (replaces `tag_bind`, replacing like it). All return `Subscription`s; values in `bw_gui.contracts.widget_events`.
- `bw_gui.runtime.topmost_window(w)`: the toplevel Escape may close from the main window -- the most recent overlay-stack entry with a toplevel, never `TRANSIENT`, honouring `PopupPolicy.close_on_escape`; replaces consumer popup registries' `active_popup()` (`docs/OVERLAY_STACK_CONTRACT.md`).
- `ScrollablePopupWindow(..., overlay_category=OverlayCategory.NON_MODAL_POPUP)`: a popup can register as a non-modal tool window in the overlay stack (default stays `MODAL_DIALOG`; `MENU`/`TRANSIENT` raise `ValueError`). Non-modal popups gate shortcuts only under `blocking(include_non_modal=True)`; Escape and `active_popup()` treat both alike.
- `bw_gui.runtime.PointerGroup(anchor, name)`: one shared pointer tag for many widgets (`add`/`discard`, `on_click`, `on_wheel`; `docs/POINTER_CONTRACT.md`) -- for grids and tables that rebuild many cells, without per-widget tags, channels or `<Destroy>` bookkeeping. Members count as wheel-subscribed for the scroll resolver.
- `bw_gui.runtime.on_global_click(anchor, handler, *, button=PRIMARY, owner=None)`: interpreter-wide click observer on the `all` router (cannot consume; replaces consumer `bind_all("<Button-1>")`), documented in `docs/POINTER_CONTRACT.md`. With `owner`, the observer is removed from the router when that widget is destroyed (e.g. a dialog closing its selection overlay on outside clicks).
- `bw_gui.testing.keys.press_key(widget, keysym, *, char="", state=0) -> bool`: headless key press through every bw-gui keyboard dispatcher on the widget's bindtags (widget binder, `on_key`, window binder, `all` router) in Tk order, without OS keyboard focus; returns whether a dispatcher reported `HANDLED`. Native class bindings are not simulated.
- **Overlay stack** (`docs/OVERLAY_STACK_CONTRACT.md`, `bw_gui.runtime.overlay_stack`): one per-interpreter stack with categories `MODAL_DIALOG`/`NON_MODAL_POPUP`/`MENU`/`TRANSIENT`; scrollable popups, the settings dialog, menu popups, tooltips, the drag ghost and native dialogs (`_run_modal`, as modal invocation without toplevel) register themselves. Presets `blocking(w, include_menus=..., include_non_modal=...)` and `modal_affecting_mode(w)` for binders' `dialog_open`. `ScrollablePopupWindow` closes on Escape through a window binder.
- **Pointer contract** (`docs/POINTER_CONTRACT.md`): `bind_wheel` (normalised `steps`, deterministic `whole_steps`), `bind_click` (`count=1|2` via Tk multi-click recognition), `bind_drag` (full lifecycle, `cancel_on_escape` independent of focus) in `bw_gui.runtime.pointer`; pure part in `bw_gui.contracts.pointer`.
- `bw_gui.testing.line_limits`: shared check for the 300-executable-line file limit. `count_executable_lines` skips blank lines, comment lines, docstrings and imports (over all lines they span); `check_repo(repo_root, arch_doc)` checks the touched Python files (working tree against `HEAD` plus untracked files; the last commit's files when the tree is clean) or explicit `paths`. Data modules are exempt via `# line-limit: data-only` (refused when the file defines functions or classes); justified exceptions are read from the architecture doc section "Ausnahmen 300-Zeilen-Regel" or "Line-limit exceptions". Files with a UTF-8 byte-order mark are read correctly. Command line: `python -m bw_gui.testing.line_limits --repo .`.
- **Screen placement contract** (`docs/SCREEN_PLACEMENT_CONTRACT.md`): pure geometry in `bw_gui.contracts.screen_geometry` (`select_monitor`, `calculate_overlay_placement` with a side priority list, `calculate_clamped_position` for pointer-following objects) and the Tk side in `bw_gui.runtime.screen_placement` (`get_monitor_info` with `bounds`/`work_area`/`source`, `apply_window_position`, `place_overlay_now`). Win32 monitor calls live only in `bw_gui.runtime._win_monitors`.
- `bw_gui.testing.import_source.assert_bw_gui_from_sibling(repo_root)`: consumer test helper asserting that `bw_gui` is imported from the sibling checkout (`<repo>/../bw-gui/src` or `../../`) and never from a nested copy `<repo>/bw-gui`.
- **ScrollableImagePreview** (`bw_gui.widgets.ScrollableImagePreview`): width-fitted, vertically scrolling image preview built on `ScrollableFrame`, for e.g. a PDF page inside a popup whose control bars must stay visible. The caller passes `render(width) -> PhotoImage | None`. The render width ignores whether the scrollbar is currently shown (no render/scrollbar oscillation), re-renders only after a width change of at least 2 px (debounced), never on height changes. `refresh(scroll_to_top=...)` and `scroll(steps, "units"|"pages")` for page changes and keyboard scrolling. Documented in `docs/SCROLLABILITY_CONTRACT.md`.
- **ChoiceDialogService** (`bw_gui.dialogs.ChoiceDialogService`, `bw_gui.dialogs.ChoiceOption`): modal "pick one answer" dialog for questions that are not yes/no (e.g. Korrektor "Neue Klausur": folder with submissions vs. one large PDF to split). `askchoice(title, message, options, *, parent=None, cancel_label="Abbrechen")` shows one button per option (with optional description) plus a cancel button and returns the chosen option's `key`, or `None` for cancel, Escape and the window's close button. Invalid options (none, empty or duplicate keys) raise `ValueError` before anything is shown. Runs through the shared modal runner like the other dialog services; Escape is stopped at the dialog so a global `bind_all("<Escape>")` never sees it; Return activates the focused button.
- **CollapsibleSection** (`bw_gui.widgets.CollapsibleSection`): a `ttk.LabelFrame` subclass whose content (`.content`) collapses/expands via a ▾/▸ arrow (or a click on the title) in its title row; the title row stays visible. `collapsed` is read-only; `set_collapsed()` changes the state programmatically without callback, `toggle()` behaves like a user click. `on_toggle(requested)` runs only on user interaction; if it raises, the widget state is rolled back and the exception re-raised (side effects such as persistence are the consumer's). `labelwidget`/`text` are reserved (`TypeError` in constructor, `configure` and item assignment). Persistence stays with the consumer. Collapsed, the section shrinks to its title row (a zero-height placeholder works around Tk keeping a master's size after its last slave is `pack_forget()`-ten).
- **Checkbox and Switch** (`bw_gui.widgets.Checkbox`, `bw_gui.widgets.Switch`; contract in `docs/TOGGLE_CONTRACT.md`). These are the only binary controls from now on. They are modern, themed indicators (a rounded box with a check mark or dash, and a pill switch with a knob) and follow the effect-timing contract:
  - **Checkbox** means staged selection that takes effect only on a submit action. Its optional `on_select` may change local presentation state only.
  - **Switch** means immediate effect. Its `on_change` is required.
  - Both pass the *requested* bool to their callback, and only on user interaction. A programmatic `variable.set`/`set_mixed` never fires the callback.
  - Both support an optional **mixed** state (`set_mixed`, `mixed_click_target`).
  - Both roll back the value and the mixed flag if the callback raises.
  - Indicators adapt to all themes, including a contrast guard that keeps at least 3:1 at every theme intensity, and to display scaling from 100 % to 200 %.
- `bw_gui.testing.checkbutton_guard`: AST guard for consumer repos. `find_offenders(app_root)` reports raw Tk/ttk checkbuttons (also through bw-gui's `ui`/`widgets` aliases, `from … import Checkbutton [as X]`, star imports and subclasses) and native menu checkbuttons. The detected and deliberately undetected forms are listed in the module docstring.
- `Checkbox`/`Switch(..., show_text=False)` for matrix cells: the mandatory label is shown as a hover tooltip.
- Menus: `MenuItem(type="switch")` and the new fields `mixed`, `on_toggle(requested)` and `mixed_click_target`. Binary menu entries show the same indicators as the widgets. For native `tk.Menu`s, `add_menu_switch`/`add_menu_checkbox` replace `add_checkbutton` with the same semantics.
- **Keybinding contract for modifiers and sequences** (`docs/KEYBINDING_CONTRACT.md`):
  - `bw_gui.contracts.key_modifiers`: `TkBackend`, `backend_for_platform`, `backend_for_windowing_system`, `KeyModifiers`, `UNKNOWN_MODIFIERS`, `modifiers_from_state`, `modifiers_from_event`.
  - `bw_gui.contracts.key_sequence`: `parse_sequence`, `declared_modifiers`, `binding_signature`.
  - `bw_gui.contracts.keybinding_conflicts`: `find_conflicts`, `definitions_overlap`.
  - These are the single place that interprets Tk's `event.state` bits and keyboard sequence syntax. Consumer apps no longer need (or may have) their own bitmask checks.
- `WindowShortcutBinder`: new generic `mode_provider` parameter (base UI mode, default `UI_MODE_GLOBAL`), new `backend` parameter (auto-detected via `tk windowingsystem`), and `allow_modifiers` on `bind()`.
- `KeybindingRegistry.find_conflicts(backend)`: semantic conflict detection (same `binding_signature` plus overlapping runtime applicability across mode, offline, dialog, text-input and modifier state).
- `bw_gui.testing.background_windows`: pytest plugin for consumer repos. Import `pytest_configure`/`pytest_unconfigure` in `tests/conftest.py`. Tk test windows then hand the OS foreground straight back to the window that was active when the session started, so a developer typing in their editor while the suite runs no longer loses keystrokes to test windows. It is a no-op outside Windows and disabled with `TK_FOCUS_TESTS=1`.
- `bw_gui.testing.tk_state_guard`: AST guard for consumer repos (tests and CI scripts). `find_offenders(app_root)` reports any direct interpretation of Tk `event.state` bits (`x.state & ...`, `getattr(x, "state") & ...`). It also follows local aliases such as `state = getattr(event, "state", 0)` (tracked per function) and reads sources with a BOM. There is one implementation instead of a copy per repo.
- Headless `WindowShortcutBinder` tests (window test double, no focus needed). The real-Tk key-routing tests take the keyboard focus, so they are opt-in via `TK_FOCUS_TESTS=1`.
- Opt-in live test `tests/live/test_live_keyboard.py` (`BW_GUI_LIVE_KEYBOARD=1`, win32) that verifies the modifier masks against real key strokes.
- `WrappedTextField.get_raw()`: returns the exact text (`Text.get("1.0", "end-1c")`) without any normalization. No stripping, no line-ending conversion, no Unicode normalization. Round trip `get_raw() == s` after `load(s)`/`set(s)`, tested with `\r`, `\r\n`, NUL, U+2028, emoji/ZWJ sequences, combining characters, surrounding whitespace and long lines. Meant for raw editing such as Merkweiser notes; `get()` keeps stripping.
- `WrappedTextField.load(value)`: loads the initial content of an editing session. It replaces the text, then clears the undo/redo stacks, resets the modified flag (this can fire `<<Modified>>` if the flag was set) and puts the cursor at the start. Ctrl+Z right after opening no longer empties the field. `set()` is unchanged and stays undoable, for replacements during editing.

### Removed
- `bw_gui.theming.theme_scrollbar`: scrollbars colour themselves now (no consumer used it).

### Fixed
- **Menus and tooltips no longer flash in the top-left screen corner:** popups of the menu bar, submenus, description flyouts and `HoverTooltip` appeared at `+0+0` for a moment before jumping into place, which felt like a lag when opening a menu. They now stay hidden until they sit at their final position (`screen_placement.new_overlay_window`, revealed by `place_overlay_now`).
- **A menu whose entries are all disabled stays open:** a top-level popup with only disabled rows (for example a single hint line) closed again right after opening, because it never took keyboard focus. Every real popup now takes focus (Escape closes it), and only description flyouts stay focus-free (`open_popup(..., description_flyout=True)`).
- `DataGrid` splitter handles were a raised 3D bevel in system grey that stood out in dark themes; they are now a flat gap in the theme's window background.
- `TextSurface.transact` rolls back an edit whose `delete` succeeded before its `insert` failed (previously only fully applied edits counted, so the deleted text stayed gone). It still never undoes when nothing changed.
- `DataGrid`: the last row could hide under a region's horizontal scrollbar. The visible height was the tallest region body (the one without a scrollbar), and the grid did not re-clamp when the scrollbar appeared at the bottom end. It is now the shortest body and is re-clamped on every body resize.
- `DataGrid` scrolled in the wrong direction (mouse wheel, touch panning, Shift+wheel/horizontal swipe): it subtracted `whole_steps`, which is positive towards the content end. It now uses `wheel_axis` like every other surface.
- Theme listeners end when their widget is destroyed, inside `register_theme_listener` itself (owner is a widget, or the new `widget=` argument). Before, `icon_button` listeners kept running after their button was destroyed. With a second interpreter that was already gone, every theme switch then raised `TclError: can't invoke "image" command: application has been destroyed`. The `on_destroy` special cases in `Scrollbar` and `DataGrid` are gone.
- Pointer and lifecycle hooks (`bind_click`, `bind_wheel`, `bind_drag`, `bind_hover`, `on_resize`, `on_focus_change`, `on_visibility`, `on_text_modified`, `on_tab_changed`, selection hooks) no longer keep a destroyed widget alive. Their Tcl command used to live on the interpreter root (`bind_class`), so each handler, and the widget its closure references, survived until the program ended. The command now belongs to the widget and is deleted with it.
- `on_destroy` no longer keeps its widget alive until the interpreter root is destroyed. Its binding moved from the bw tag (command owned by the root) to the widget's path tag (released with the widget).
- `Scrollbar` meldet ihren Theme-Listener beim `<Destroy>` ab (vorher erst beim nächsten Theme-Wechsel; war der Interpreter da schon zerstört, warf die Prüfung `winfo_exists()` einen `TclError`).
- `icon_button` recolors through a theme listener per button; its registry no longer keeps destroyed buttons alive (weak keys instead of a global list).
- `tk_state_guard` now also finds a state alias assigned through `or`/`and`/`if-else`, e.g. `state = int(getattr(event, "state", 0) or 0)` (bug 4).
- `Checkbox`/`Switch`: only plain Space (Shift tolerated) activates a focused toggle. Tk's class binding `TCheckbutton <Key-space>` also fired for Ctrl+Space/Alt+Space (Cmd/Option on aqua), against the exact-modifier keyboard contract - a focused "finished" switch swallowed an app's Ctrl+Space shortcut and toggled itself instead. More specific no-op class bindings (installed once per interpreter by the first toggle, no `break`) let those keys travel on to window and application shortcuts.
- Pointer hooks invalidate their subscription on the destroy of a wrapper owner (e.g. `ScrollablePopupWindow`) too: the destroy match is by Tk path instead of identity.
- `humanize_shortcut`/`compose_hover_text` accept free display texts again (`"Entf"`, `"Strg+T"`, `"Leertaste"`) and normalize them as before the `KeySpec` rebuild; only Tk binding syntax (`"<Control-s>"`) raises `ValueError`. Since the rebuild, a localized hover shortcut made app start-up fail (e.g. Kartograph).
- Mouse wheel over a text field, list, tree, combobox or scrollbar inside a scrollable panel no longer scrolls the panel as well; a wheel over a small inner area that does not scroll moves the surrounding panel; wheel events in a popup never scroll the main window; scrolling over a panel's border or own scrollbar scrolls that panel. Alt menu mnemonics and menu keyboard navigation run through the keyboard router (behaviour unchanged).
- Menus, submenus, description flyouts, tooltips and the drag ghost now stay on the monitor (and work area, i.e. above the task bar) of their anchor or cursor on multi-monitor setups. Menu popups flip above/left when they do not fit below/right; a menu taller than the screen is capped and scrolls. Dialog centering (`center_window_over_parent`) clamps to the work area instead of the full monitor. The drag ghost uses theme colours instead of hard-coded light yellow.
- `KeyBindingDefinition.allow_modifiers` is now actually enforced by `evaluate_runtime` (it was documented but ignored). Contexts carrying modifier information (`WindowShortcutBinder`) block shortcuts while an undeclared Control/Alt/Command is held. An undecodable state is blocked fail-closed. Shift, NumLock and CapsLock never block. Contexts without modifier information (`modifiers=None`) behave as before. See `docs/KEYBINDING_AUDIT.md` for the consumer audit (only Namenfit changes: Ctrl/Alt + Return/Space/BackSpace/Escape no longer fire its shortcuts).
- `WindowShortcutBinder` no longer silently overwrites a binding when a second one with the same (or semantically equal, e.g. `<Control-,>`/`<Control-comma>`) sequence is registered. Each signature is bound once and multiplexed by runtime scope, and overlapping duplicates raise `ValueError` at bind time.
- `docs/QUICKSTART.md`: the "If `import bw_gui` fails" checklist no longer names a machine-specific absolute path, so it holds for any clone location. It now describes the sibling-folder lookup (`../bw-gui/src`, then `../../bw-gui/src`, then a stale local copy) that `ensure_bw_gui_on_path()` actually performs. The "See also" list no longer links to the non-existent `MENUBAR.md`, `THEMING.md`, `DIALOGS.md`, `WIDGETS.md` and `LAUFKERN.md`. It points to `ARCHITECTURE.md`, `THEME_CONTRACT.md`, `TOGGLE_CONTRACT.md`, `SCROLLABILITY_CONTRACT.md` and the source packages `src/bw_gui/menu|dialogs|widgets|laufkern/` instead.

### Changed
- **Shortcut display in German, one formatter:** `humanize_shortcut` (and everything built on it: hover texts, action labels) shows keys in German (`Strg+Shift+L`, `Strg+Entf`, `Esc`, `Pos1` …) from one table; code and configuration keep the English `KeySpec` notation. `KeySpec.notation_parts()` is the one decomposition used by `str(spec)` and the display. New `compose_menu_label(label, shortcut)` for menu texts (`Label (Strg+Z)`). `bind(..., metadata=)` and `KeybindingRegistry.shortcut_for_intent(..., metadata=)` (also in `compose_hover_text_for_intent`) tell bindings of one intent apart for displays, e.g. move left/right. Affects every app's tooltips (previously English `Ctrl+…`).
- `tinted_color` (and everything built on it) raises `ValueError` for a tint or `base_token` that is neither `#RRGGBB` nor a token of the active theme. It used to blend the name as a colour into an arbitrary grey, so a token missing from some themes (Kursplaner's next-unit header used `info_soft`) went unnoticed.
- Mouse wheel over a `ScrollableFrame`'s scrollbar (also scrollable popups and the settings dialog) scrolls exactly `SCROLLBAR_WHEEL_FACTOR = 3` times as far as over its content; formerly Tk's scrollbar binding added its own scrolling to bw-gui's by accident (5 times).
- **Breaking:** `widgets.Scrollbar` accepts only `orient`, `command` and `takefocus` (`bool | None`); any other option (`style=`, colours, sizes) raises `TypeError`. Tab traversal skips scrollbars as before.
- Settings dialog: the content area scrolls through `ScrollableFrame` (wheel over the whole panel, scrollbar only when needed).
- `bw_gui.testing.line_limits` also reads exception **tables** (path in the first cell, justification in the last) and headings that start with a known title (e.g. `GRENZE(dateigroesse): Benannte Ausnahmen (Stand ...)`), so Kursplaner's documented exceptions are recognised.
- Self guard (`tests/test_bw_gui_self_guard.py`): only `runtime/key_router.py` uses `bind_all`, and no bw-gui module binds a specific key sequence. `KEYBINDING_AUDIT.md` lists the behaviour changes per app of the keyboard migration; `TK_USAGE_INVENTORY.md` has the 2026-10-17 recount (all AST guard findings 0).
- Keyboard contract applied inside bw-gui itself: the text prompt and choice dialogs bind Enter/Escape through a window binder (the stdlib's raw bindings on the dialog are removed, Escape is consumed at the dialog), the choice buttons and `WrappedTextField` word delete (Ctrl+Backspace/Ctrl+Delete, Shift tolerated) use widget binders; `ScrollablePopupWindow._request_close`/`_handle_escape_request`/`_on_escape_close` no longer return Tk's `"break"` (the binder consumes the key).
- `WrappedTextField(initial=…)` now uses `load()`: the pre-filled text can no longer be undone into an empty field. No current consumer passes `initial=`, so existing behaviour does not change.
- **Breaking: keyboard contract rebuilt on `KeySpec`** (`docs/KEYBINDING_CONTRACT.md`). Shortcuts are described with `KeySpec` (`KeySpec.char("z", {Mod.CTRL})`, `KeySpec(Key.ESCAPE)`, notation `KeySpec.parse("Ctrl+Shift+Z")`); modifiers are exact, extra modifiers only via `tolerate`, Shift tolerance on characters via a second spec. `KeyBindingDefinition.sequence`/`allow_modifiers`, `bw_gui.contracts.key_sequence` (`parse_sequence`, `binding_signature`) and `humanize_shortcut_sequence` are removed (`humanize_shortcut` accepts `KeySpec` or a display text). Handlers receive a `KeyEvent` and return `EventResult` (`None` = not handled); string returns raise `TypeError`. New `ApplicationShortcutBinder` (cross-window), `WidgetShortcutBinder`, `on_key(phase="before"|"after")`, text-input contract (`accepts_text_input`, `register_text_input`; read-only combobox and disabled entry are no text input any more). One keyboard catch-all per bindtag; the `all` tag is owned by a per-interpreter router installed by `TkRootHost` right after `Tk()` (Tk defaults are wrapped Tcl-safely and keep working).
- **Breaking:** `bw_gui` no longer re-exports `ui`, `widgets` and `fonts` at the top level. Import them from `bw_gui.runtime`. The top-level `widgets` (the ttk module) shadowed the `bw_gui.widgets` package, so `import bw_gui.widgets.toggles as t` failed.
- Settings dialog: bool fields with `live_apply` (and an `on_live_apply` callback) are now **Switches** that take effect at once. All other bool fields are **Checkboxes** that take effect on Apply/Save. The label is now part of the toggle and is clickable.
- Settings dialog: **Cancel keeps live-applied values**. Staged values are still discarded. If a live value changed, `on_commit` receives the last committed configuration with the current live values, so the saved configuration matches what is in effect. Programmatic changes to a live bool field no longer trigger `on_live_apply`.
- Custom menu bar: checkbox entries show the themed indicator instead of ☑/☐.
- `KeybindingRegistry.conflicts()` is deprecated in favour of `find_conflicts()`, because it compares raw sequence strings.

### Changed
- `BwBaseWindow` (and `AppShellConfig`) now open the main window **maximized by default** (`start_maximized: bool = True`, applied as `root.state("zoomed")` right after `geometry`/`minsize`). `geometry` remains the size the window returns to when un-maximized. Pass `start_maximized=False` for the previous behavior. Affects every app built on `BwBaseWindow` (Blattwerk, Kursplaner, Korrektor, Namenfit); dialogs/popups (`ScrollablePopupWindow`) are unaffected. Apps that restore a remembered window size must call `root.state("normal")` before `root.geometry(...)`.

### Added
- `ScrollableFrame(orient="horizontal")` and `ScrollableFrame.see_x_range(left, right)`: horizontal counterpart for single-row strips whose natural width can outgrow their space (first consumer: Blattwerk's document tab strip). The content keeps its natural width, the Canvas requests exactly that width (a fitting strip shrink-wraps, an overflowing one is clipped and scrollable), a horizontal scrollbar appears below only while it overflows, and the mousewheel scrolls horizontally through the existing single per-interpreter dispatcher. Vertical behavior is unchanged; the private scrollbar attributes were generalized from `_v_scroll`/`_v_scroll_visible` to `_scrollbar`/`_scrollbar_visible`. `docs/SCROLLABILITY_CONTRACT.md` documents the new mode.
- New `bw_gui.widgets.ScrollableFrame`: a real `ttk.Frame` subclass that is itself a scrollable viewport (vertical Canvas+Scrollbar, `.content` as the build target, no `__getattr__` delegation needed since it already is the widget) - the shared SSOT for embedded, non-popup scrolling (see new `docs/SCROLLABILITY_CONTRACT.md`). The scrollbar itself is only shown while content actually overflows the viewport and hides again the instant it does not (re-evaluated on every content-/canvas-size change, e.g. a `PanedWindow` splitter drag or a window resize), snapping back to the top when it hides - never a bar that just sits there unneeded. Mousewheel is dispatched through exactly one `bind_all` per Tk interpreter, registered once for that interpreter's whole lifetime (not per instance, and not re-registered if every instance is ever destroyed and a new one created later), so any number of simultaneously visible `ScrollableFrame`s - including ones nested deep inside `PanedWindow` panes - never clobber each other's binding or double up a single wheel click, and a wheel event over any child widget inside `.content` still resolves to the right instance.
- New `docs/SCROLLABILITY_CONTRACT.md`: documents the bw-gui-wide scrollability convention - popups and embedded content areas are scrollable *by default* (`ScrollablePopupWindow`/`ScrollableFrame` respectively), not only once content "probably doesn't fit"; deviations require a documented reason.

- Fixed `CustomMenuBar` popups closing themselves prematurely (before the user could pick a different row) while hovering or arrow-keying between rows, especially ones with a `description`. Cause: internal `.focus_set()` calls this menu makes to juggle focus between its own popups (e.g. the Windows destroy-while-focused-popup fix below) looked, to the existing click-away watchdog, identical to the user clicking elsewhere. Fixed with a reentrant `_focus_watchdog_suspended()` context manager wrapping every such internal operation (`open_popup`, `_show_item_description`, `_on_menu_back_key`, `_execute_menu_command`): the watchdog is suspended for the operation's whole duration and re-armed with exactly one check against its true final focus state once it completes, rather than reacting to every intermediate hop.
- `CustomMenuBar` popups are now keyboard-navigable: Up/Down move the highlighted row (wrapping), Enter/Return activates it (opens a submenu or runs its command), Right opens a highlighted submenu, Left/Escape closes back to the parent popup (or closes everything at the top level). Every popup takes keyboard focus and highlights its first row as soon as it opens — from a mouse click or from keyboard activation alike — so arrow-key navigation works immediately without a prior mouse hover.
- `MenuItem.description`: optional explanatory text shown, on hover over a menu row, as a non-interactive, submenu-positioned flyout (`CustomMenuBar._show_item_description`) — not a generic tooltip: no open delay, immediate seamless replacement between sibling descriptions, stays open for as long as the surrounding popup context stays open, and is torn down only via the existing `_popup_stack` lifecycle (replacement, or the popup context closing). See `MenuItem`'s docstring for the full contract. Keyboard navigation (above) triggers the same description flyout as mouse hover when the highlighted row has one.
- `bw_gui.widgets.DragDropController`: a minimal press-drag-release primitive for small assignment UIs (drag a widget's payload onto a registered drop-target widget, resolved by widget containment/parent-chain walk at release - not a general DnD framework, no OS-level drag-and-drop). Built for korrektor's Kategorien-Zuordnung (Aufgaben per drag onto named buckets); `_resolve_drop_callback` unit-tested with fake widgets (`tests/test_drag_drop.py`), rest verified via a real-Tk smoke test.
- `bw_gui.theming.recolor_photo_domain(photo, *, light_color, dark_color)`: recolors a `PhotoImage`'s opaque pixels to a consumer-owned color pair, theme-aware — the `PhotoImage` counterpart to `canvas_domain_fill`/`canvas_domain_outline` for icons whose color comes from domain-owned constants (e.g. a lesson-type or achievement-category color) rather than a bw_gui contract token. Reuses the same internal `_recolor_photo` pixel-/alpha-handling as `recolor_photo`/`recolor_photo_token`.
- `SettingsFieldSpec.visible_when` for conditional field visibility in the tabbed settings dialog: a field only renders while a named sibling field currently holds a given value (e.g. a fixed-cutoff-time field that only appears once a mode field is switched to "fixed"). Validated against unknown field references, wired via the existing section-rerender-on-change mechanism (no separate show/hide widget bookkeeping).

### Fixed
- `ScrollablePopupWindow`: Schließen (Fensterknopf/Escape) blendet das Fenster jetzt sofort per `withdraw()` aus, bevor der Widget-Baum zerstört wird — vermeidet einen sichtbaren Teardown-Effekt bei Popups mit vielen/verschachtelten Widgets (z. B. `Panedwindow` mit mehreren Kind-Frames), bei dem die Widgets beim Schließen sichtbar kollabierten, bevor das Fenster verschwand. `_request_close()` ist zusätzlich idempotent (ein `_closing`-Guard verhindert einen doppelten `destroy()`-Aufruf, falls zwei Close-Pfade kurz hintereinander feuern).
- `ScrollablePopupWindow`: Escape schließt das Popup jetzt immer, unabhängig vom Fokus. Vorher wurde bei fokussiertem Eingabefeld (Entry/Text/Spinbox/Combobox) nur erneut `focus_force()` auf das ohnehin schon fokussierte Popup-Fenster aufgerufen — das hatte keine sichtbare Wirkung, Escape schien beim Tippen wirkungslos.
- `TextPromptDialogService.askstring(...)`: Escape im Textprompt-Dialog stoppt jetzt zuverlässig am Dialog, statt bis zu darunterliegenden Fenstern weiterzulaufen (z. B. einem globalen `bind_all("<Escape>")`-Handler der aufrufenden App). Ursache war der eingebaute `tkinter.simpledialog.Dialog.cancel`, der `None` statt `"break"` zurückgab.
- Popups und Tooltips wurden bisher immer auf dem primaeren Monitor positioniert, auch wenn das App-Fenster auf einem anderen Monitor lief. Die Positionierung berechnet jetzt den zustaendigen Monitor anhand der aktuellen Fensterposition und platziert Popups korrekt auf dem richtigen Bildschirm.

### Changed
- `ScrollablePopupWindow` now builds its scrollable content area directly on `bw_gui.widgets.ScrollableFrame` instead of maintaining its own parallel Canvas/Scrollbar/mousewheel implementation - only Toplevel lifecycle (creation, geometry, theme injection, modal focus, Escape/close handling) stays in this class. The previously dead horizontal scrollbar (`_h_scroll` - already non-functional, since content width was always forced to match canvas width) is gone; a repo audit (bw-gui, korrektor, blattwerk, namenfit, Kursplaner) found no consumer relying on it - see `docs/SCROLLABILITY_CONTRACT.md` for the audit note.
